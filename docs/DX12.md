# DirectX 12 backend

The Windows production backend is registered as `dx12`; it never substitutes
the contract-test null backend. Configure with `VITARECOMP_ENABLE_DX12=ON`
(the Windows default). The target links only Windows SDK `d3d12` and `dxgi`.

## Adapter and device policy

DXGI hardware adapters that can create a Direct3D 12 feature-level 11.0 device
are enumerated first in high-performance preference order. Adapter index zero
is therefore the default hardware choice when hardware exists. WARP is appended
as a software adapter named with `[WARP software; explicit selection]`; callers
must enumerate and select that index deliberately. Adapter records include
DXGI IDs, memory sizes, LUID-derived platform identity and UUID, type, and
queried shader capabilities.

Each device owns one direct command queue. The renderer-neutral graphics,
compute, and copy queues are serialized onto it, preserving submission order
and timeline-fence semantics. Three reusable frame contexts provide command
allocators/lists and an internal fence/event. Application fences are native
`ID3D12Fence` objects.

When `VITA_GPU_DEVICE_ENABLE_VALIDATION` is requested, device creation requires
the Windows D3D12 debug layer and installs an `ID3D12InfoQueue`. Corruption and
error messages turn the API operation (and therefore conformance) into a
failure. DRED breadcrumbs and page-fault reporting are enabled before device
creation. Device removal reports both the failing HRESULT and
`GetDeviceRemovedReason`, with DRED details when available.

## Contract mapping

The backend implements:

- Win32 `HWND` flip-discard swapchains, acquire/present, tearing checks,
  minimize/restore, nonzero resize, and deterministic idle shutdown;
- RTV, DSV, shader-visible CBV/SRV/UAV and sampler heaps with reusable ranges;
- GPU-only, upload, and readback buffers, initial buffer uploads, typed and
  structured UAVs, textures and texture initial-data staging;
- render/depth views, samplers, binding layouts/sets, descriptor updates, DXIL
  shaders, graphics and compute pipelines;
- tracked transition/queue barriers, render passes, viewport/scissor, vertex
  and index buffers, push constants, draw/indexed draw/dispatch, copies,
  markers, submission, timeline fence waits, and mapped readback; and
- swapchain texture readback with the contract's explicit 256-byte row pitch
  and 512-byte placement alignment.

Vertex attributes map to `TEXCOORD<location>`. Push constants map to root
constants at `b0, space32767`. Shader code using either feature must follow
those conventions.

Operations that cannot be represented safely fail explicitly. Examples are
runtime HLSL compilation (`VITA_GPU_ERROR_SHADER_COMPILER_UNAVAILABLE`), PIX
capture integration (`VITA_GPU_ERROR_UNSUPPORTED`), depth/stencil readback
through the contract's single-plane copy descriptor, and illegal state
transitions or UAV storage descriptors on upload/readback heaps. They never
return synthetic success.

The public resize call requires a nonzero extent. During Win32 minimization,
keep the existing buffers and defer `vita_gpu_swapchain_resize` until
`WM_SIZE` reports a restored nonzero client area.

## Conformance and WARP

The framework-owned shader is
`tests/shaders/gpu_conformance.hlsl`, shared with Vulkan conformance. Generated
DXIL and SPIR-V stay in the build tree.
The pinned compiler contract is:

```text
release: v1.8.2505.1
binary:  1.8.2505.32
```

Configure a Debug conformance build after extracting that official Microsoft
release:

```powershell
cmake -S . -B build\dx12-debug -G Ninja `
  -DCMAKE_BUILD_TYPE=Debug `
  -DVITARECOMP_BUILD_DX12_CONFORMANCE=ON `
  -DVITARECOMP_DXC_ROOT=C:\tools\dxc-v1.8.2505.1
cmake --build build\dx12-debug
ctest --test-dir build\dx12-debug -R gpu-dx12 --output-on-failure
```

`vitarecomp_dx12_conformance` defaults to the first hardware adapter. Its
`--warp` option explicitly selects WARP; `--hidden` creates a real hidden
top-level window for unattended CI. The CTest WARP run renders clear plus a
triangle, presents, minimizes/restores, resizes, validates deterministic
readback, and repeats complete startup/shutdown three times. The separate
`gpu-dx12-warp-buffer` test covers adapter ordering, upload, copy, fence, and
readback without shaders or an interactive window.

The conformance executable enables backend validation whenever Windows
Graphics Tools makes the D3D12 debug layer available. If it is unavailable,
the executable prints a warning and continues so WARP CI remains usable on a
minimal Windows image. Applications that explicitly set
`VITA_GPU_DEVICE_ENABLE_VALIDATION` still fail device creation rather than
silently running without the requested debug layer.
