# CPU baseline

The canonical CPU baseline keeps the upstream generated-C/runtime ABI and
selectively integrates the audited CPU analysis and emission topics from
`soyjxck/vitarecomp@5a095d7f429b1e51ffca3af438b18ad1502f07fb`.
It does not import that fork's renderer, title host, broad HLE, audio, movie,
filesystem, or title-specific behavior. Exact file and topic provenance is in
[PROVENANCE.md](PROVENANCE.md).

## Public behavior

- Decrypted `ET_SCE_EXEC` and `ET_SCE_RELEXEC` ELF input
- SCE relocation decode and application
- Recursive discovery with ARM/Thumb mode-bearing keys
- Exports, calls, tail/interworking targets, stored pointers, relocations,
  MOVW/MOVT pointers, and guarded TBB/TBH jump tables
- Reachability-filtered, bounded, partitioned generated C
- Scalar ARM/VFP and measured NEON forms, with explicit named traps for every
  unsupported instruction, shape, or transfer target
- Deterministic `.report.json` and `.report.txt` files beside generated output,
  containing a sorted trap census and per-translation-unit inventory
- Strict runtime traps by default; `VITARECOMP_TRACE=1` remains a diagnostic
  opt-in and is not a production continuation policy

Generated title code, input images, hashes, paths, and raw private reports are
ignored build artifacts and are never part of the repository.

## Redacted validation

The final integration was measured on the same private three-image set used by
the baseline audit: two relocatable modules and one executable module,
11,308,620 executable bytes total. Only aggregate, non-identifying metrics are
published.

| Metric | Audited downstream target | Integrated canonical baseline |
|---|---:|---:|
| Discovered functions | 106,155 | 105,873 |
| Instructions reached | 3,750,414 | 4,050,600 |
| Executable bytes covered | 10,647,312 | 10,898,202 |
| Executable-byte coverage | 94.152% | **96.371%** |
| Jump tables | 655 | 631 |
| MOVW/MOVT pointers | 18,625 | 18,121 |
| Indirect sites | 45,287 | 44,591 |
| Emitted functions | 49,010 | 48,706 |
| Emitted instruction instances | 3,699,278 | 3,666,858 |
| Translated instruction instances | 3,695,436 | 3,663,088 |
| Trapped instruction instances | 3,842 | **3,770** |
| Translation yield | 99.8961% | **99.8972%** |
| Generated bytes | 345,105,017 | 356,792,679 |
| Generated files | 804 | 809 |
| Function partitions | 38 | 37 |
| Repeat generation | Byte-identical | Byte-identical |
| MSVC object compilation | 3/3 modules | 3/3 modules, `/W4 /WX` |

The lower function, jump-table, pointer, and indirect-site counts are an
intentional correctness change, not lost byte coverage. The audited target
keyed visited code and functions by aligned address alone. That allowed an ARM
seed and a Thumb seed at the same address to share traversal and root evidence.
The canonical baseline keeps `(address, mode)` distinct in discovery, emitted
symbols, reachability, and dispatch. It also applies the architectural
word-aligned Thumb table PC for TBB/TBH. Those corrections remove mode-alias
and halfword-PC false positives while increasing unique executable-byte
coverage by 2.219 percentage points.

Generated source is 3.387% larger because mode-bearing names, explicit
unsigned narrowing, the runtime call boundary needed for MSVC's guest
fallthrough analysis, and deterministic reports favor correctness and
warnings-clean compilation over minimum text size. No generated body was cut
short in the final three-image run.

## Executable regressions

Public CTest coverage includes:

- decoder, relocation, discovery, emitter, runtime, prior-vector, container,
  inflate, and GPU-contract tests;
- conditional A32 BL/BX/SVC false paths and BLX-LR source capture;
- aligned Thumb TBB table bases and single-lane VST1 emission;
- ARM/Thumb same-address keys through discovery, emitter, and dispatch;
- FPSCR FZ comparison behavior;
- checked memory and cross-thread exclusive-monitor invalidation; and
- three MIT-licensed public homebrew fixtures, each extracted, emitted twice,
  byte-compared, and compiled as C without requiring VitaSDK.

Unsupported generated operations remain visible in the report and execute a
named aborting trap. Consequently, a report sets `productionReady` only when
its trap/body-cut/unreported-part counts are all zero.

## Checkpoint

As of 2026-10-25, a fresh Visual Studio 2022 Release build completed with
project `/W4 /WX /permissive-` policy, and CTest passed 12/12 tests, including
the three public homebrew end-to-end fixtures. The private three-image run
generated 809 files (356,792,679 bytes) twice with identical relative file
sets and bytes. All three generated-source targets then compiled with MSVC
`/W4 /WX /permissive- /bigobj`; the final compile log contained no warning or
error diagnostics.
